# 手机全景补全为 360° / 720° 全景 —— 效果较好的开源可商用技术方案调研报告

> 调研时间：2026-11-09
> 问题定义：用户拿手机拍摄得到的是**残缺/柱面全景**（多为水平 360° 带，天顶、脚下缺失，或只拍了部分角度），需要把它**补全成完整的 360° 柱面全景或 720° 球面全景**（含正上 zenith、正下 nadir，边缘无缝）。
> 目标约束：只看**开源**、且**许可证允许商用**的技术方案；对高效果但禁止商用的方案单列「避坑」。
> 结论口径：License 均通过 GitHub API + LICENSE 原文逐条核实（见文末链接）；效果/显存等以各仓库与论文为准，未逐一实测，落地前需自测。
> 与其他文档关系：本篇聚焦「**补全 / 外扩（completion & outpainting）**」，与同目录《AI 全景图生成技术现状调研报告》（偏文本→全景生成）、《全景拼接技术调研报告》（偏传统拼接）、《全景景深估计技术调研报告》互补、不重复。

## 二、先厘清「360 与 720」和补全的四个子问题

「手机全景补全成完整全景」在技术上不是单一模型，而是四个子问题，方案各管一段：

第一，**拼接成骨架（Stitching）**：把手机移动拍的多张/视频帧拼成一张等距柱状全景。这一步是确定性的，传统 **OpenCV Stitcher（Apache-2.0）**、**Hugin（GPL-2.0+）** 就能干，产出通常是**只有水平带**的 360° 图，天顶与脚下是黑的或缺的。

第二，**极区修补（Zenith / Nadir fill）**：720° 的关键就是补正上（zenith）和正下（nadir）。传统做法是**手工在 PS 里 patch**（全景摄影师的日常苦活），或买双鱼眼全景相机。开源里 **PanoTwist（GPL-3.0）** 专门处理 nadir 极点旋转，**LaMa（Apache-2.0）** 可对天顶/脚下的 mask 做补洞。

第三，**生成式外扩（Outpainting / Completion）**：把只拍了一半、或有缺角的全景，用深度学习「无中生有」补成完整球面。这才是「补全」的核心与难点，代表是 **PanoDiffusion（非商用）**、**Cylin-Painting（MIT）**，以及可改造成补全的生成底座 **DiT360 / Canvas360（MIT）**。

第四，**球面几何一致性**：equirect 投影两极严重拉伸、左右 ±180° 要无缝环绕、上下不能穿帮。这是补全质量的分水岭——DiT360 的 circular padding + yaw loss + cube loss、Cylin-Painting 的 wrap 约束、PanoDiffusion 的 latent alignment 都是在解这一个问题。

一句话：**你要的「手机拍不全→补成完整 360/720」，可商用最优解通常是「确定性拼接/补极区（第一、二步）＋ 生成外扩（第三步）＋ 用球面感知的方法保一致性（第四步）」的组合，而不是指望单个模型端到端。**

（补充：若「720 全景」在你的语境里指**全景视频**而非图片，则属于 immersive video inpainting，另一条更重的赛道，本报告不展开，可另立调研。）

## 三、核心发现：最出名的补全方案大多禁止商用

这是本次调研对企业最关键的一条，先讲透。用 GitHub API 拉 LICENSE 原文核实的结果：

- **PanoDiffusion**（360 扩散外扩的事实标杆、效果最好的一类）用的是 **S-Lab License 1.0**，正文明确写「**Redistribution and use for non-commercial purpose**」——**仅限非商业**，代码和权重都不能进商业产品。
- **ComfyUI-VR-Outpaint-Tools** 和 **ComfyUI-Seamless-Equirectangular**（社区做 360 外扩最顺手的两个 ComfyUI 节点）用的是 **PolyForm Noncommercial License 1.0.0**——**同样非商业**。
- 换句话说，**「效果最好」和「可商用」在纯补全模型上目前是冲突的**：最出名的那几个恰好在许可上封了商用。

因此，如果目标是「能上商业产品」，现实可选的补全主力只有 **Cylin-Painting（MIT）** 与 **3d-pano-inpainting（MIT）**，再用 **LaMa（Apache）**、**PanoTwist（GPL）**、**OpenCV/Hugin** 做确定性环节，以及用 **DiT360 / Canvas360 / PanSplat / LayerPano3D（均 MIT/Apache）** 作为可商用的生成底座去改造/兜底。下面逐个详解。

## 四、可直接商用的补全方案详解

### 4.1 Cylin-Painting（MIT，专做 360 外扩补全，可商用首选）

- **它解决什么**：论文标题即「Seamless 360° Panoramic Image Outpainting」——给一张**部分**全景（有已知区 + 待补的 mask），生成**无缝、可环绕**的完整 360° 柱面全景。正好命中「手机只拍了一半 / 缺角度」的补全。
- **技术**：图像翻译（GAN）路线，带 wrap-around 保证左右无缝、cylinder 约束保证球面一致；比扩散路线更轻、显存更友好。
- **成熟度 / 可落地性**：仓库含 `train.py / test.py / model / scripts / requirements.txt`，训练与推理代码齐全；MIT 无使用限制。缺点是分辨率与纹理上限不如扩散 SOTA，属于「够用、稳、能商用」的一档。
- **适配今鱼**：可当作「手机拍不全→补成完整 360」的**默认可商用引擎**，尤其适合做产品里那条低成本先手。

### 4.2 3d-pano-inpainting（MIT，3D 感知补洞，几何一致性好）

- **它解决什么**：单张全景里有缺失/被挡区域时，用**深度 + 网格重投影**来补，补出来的内容在 3D 里一致（IEEE VR 2024）。适合需要「补完还能左右看一点视差」的沉浸场景。
- **技术**：depth-estimation + mesh + inpainting 的流水线（仓库目录即 `depth-estimation / inpainting / mesh / results`），MIT。
- **成熟度**：工程链略重（要跑深度估计），但代码全开、许可干净；对「补极区 + 补被挡角落」比纯 2D 生成更稳。
- **适配今鱼**：当你从「照片级全景」往「可左右小幅移动的沉浸全景」走时，这是可商用的中间件；与全景景深估计报告衔接。

### 4.3 LaMa（Apache-2.0，通用大 mask 补洞，确定性兜底）

- **它解决什么**：分辨率鲁棒的大面积补洞（Fourier Conv），不是全景专用，但补**天顶/脚下、接缝、被挡物**非常好用，10k+ star、极成熟、Apache-2.0 干净。
- **用法（全景）**：把 equirect 图的天顶/脚下/破损区做成 mask，喂给 LaMa 补；需自行处理左右 wrap（把图横向镜像拼接再裁，保证接缝连续）。
- **定位**：**质量兜底与「先跑通」的首选**——在很多产品里，「Cylin/扩散外扩生成主体 + LaMa 补极区和接缝」是可商用的稳健组合。

### 4.4 PanoTwist（GPL-3.0，脚下极点确定性修复）

- **它解决什么**：等距柱状全景正下（nadir）极点的旋转拖影，用确定性的「twist」变换做极点修复，比人肉 PS 快。
- **许可**：GPL-3.0，**可商用**，但属强 copyleft——如果你把它**分发**进客户端或作为可分发软件交付，衍生部分要一并开源；若仅在服务端内部使用（不对外分发软件本身），GPL 义务通常不触发。今鱼是 SaaS/小程序交付形态，**集成方式要走法务确认**（避免被迫开源自有代码）。

### 4.5 OpenCV Stitcher / Hugin（确定性拼接骨架）

- 多张手机重叠照片 → 一张全景底图，CPU/桌面即可、许可干净（Apache-2.0 / GPL-2.0+）。它们只给「有盲区的骨架」，之后仍需上面 4.1–4.4 补全极区与缺角。适合做**补全前的预处理**。

### 4.6 MIT/Apache 的生成底座（可作补全的二次开发引擎）

这些不是「补全模型」，但许可干净、效果好，可当底座改造成补全，或直接用其生成能力补内容：

- **DiT360（MIT，CVPR 2026）**：当前 360 生成 SOTA（FID 42.88），球面一致性三重约束成熟；「in-context 版」改造或作为局部重画的生成器是可行方向。
- **Canvas360（MIT，Insta360 2026）**：几何感知的 **in-context** 全景生成，天生适合「给一点条件、补出上下文」的范式，是最值得关注的可商用补全底座。
- **PanSplat（MIT，CVPR 2025）**：4K 前馈、极快，适合有输入图、要高分辨率的路径。
- **LayerPano3D（Apache-2.0，SIGGRAPH 2025）**：文本→可漫游 3D 全景，做沉浸升级。

## 五、可商用性取决于基座模型的方案（SD / SDXL / Flux）

社区大量「360 扩图」其实是 **通用扩散 inpaint/outpaint + 等距柱状先验 LoRA** 拼出来的（ComfyUI 工作流是主流）。这类**能不能商用，取决于两层许可**：

第一层，**工作流/节点本身的许可**——注意 **ComfyUI-VR-Outpaint-Tools、ComfyUI-Seamless-Equirectangular 是 PolyForm 非商业**，即便你换可商用基座，这两个节点代码也不能商用。要么自研等价节点，要么用 MIT/Apache 的节点替代。

第二层，**基座大模型的许可**（决定生成权重能否商用）：

- **SD 1.5 / SD 2.x / SDXL**：CreativeML **OpenRAIL-M**，**允许商用**（附带使用限制条款，如禁止违法/伤害用途）。
- **Flux.1-dev**：flux-1-dev **非商业许可**——**默认不能商用**；要商用得换成可商用基座或走授权。
- **国产可商用基座**：通义万相 / 混元等（具体以各自协议为准）。
- **CivitAI 上的 360/equirect LoRA**：许可**逐个不同**，很多标「非商用」，必须逐条核对 LoRA 自身许可 + 其训练基座许可。

结论：**「SDXL（OpenRAIL-M）＋ 一个许可确认为可商用的等距柱状-aware LoRA ＋ LaMa 补洞」是一条现实、可控、可商用的扩散式全景补全路线**；而「Flux.1-dev 系」和「Burgstall 那两节点」在商用前要替换或排除。

## 六、效果最好但禁止商用（避坑清单）

| 方案 | 效果定位 | 许可 | 商用建议 |
|---|---|---|---|
| **PanoDiffusion** | 纯全景 outpainting 的公认标杆 | S-Lab License 1.0（非商业） | 仅可做技术预研/benchmark，**不进产品** |
| **ComfyUI-VR-Outpaint-Tools** | 360 外扩+接缝，很顺手 | PolyForm Noncommercial 1.0.0 | 自研等价节点或换 MIT/Apache 节点 |
| **ComfyUI-Seamless-Equirectangular** | 无缝 equirect | PolyForm Noncommercial 1.0.0 | 同上 |
| 部分 CivitAI 360 LoRA | 效果好但参差 | 常标非商用 / 基座为 Flux.1-dev | 逐条核实，默认排除非商用与 Flux.1-dev |

一句话避坑原则：**「论文引用最高、社区教程最多」的全景补全工具，恰恰多数封了商用；选型时先看 LICENSE 再看 demo。**

## 七、面向「手机补全」的推荐落地组合

给一套「可商用、可分阶段落地」的组合拳（许可全部干净）：

**近期 · 低成本先手（1 个月内可验证）**

1. 手机多张/短视频帧 → **OpenCV Stitcher** 拼成 360 柱面骨架（确定性、免费）。
2. 天顶/脚下与接缝 → **LaMa（Apache）** 按 equirect mask 补洞；nadir 极点旋转用 **PanoTwist（GPL，集成方式过法务）** 或 LaMa 直接补。
3. 产出「可发的 720°」。**这条纯确定性/成熟，合规风险最低，能最快兑现「手机没全景相机也能出 720」的卖点。**

**中期 · 生成式补全（提质 / 补大缺口）**

4. 当缺失角度多、需要「无中生有」时 → **Cylin-Painting（MIT）** 做 360 外扩补全；或搭 **SDXL（OpenRAIL-M）＋ 确认可商用的 equirect-aware LoRA** 做扩散外扩（务必绕开 Burgstall 非商用节点、Flux.1-dev 基座），补洞仍叠 LaMa。
5. 需要 3D 一致/可小幅移动视差 → 引入 **3d-pano-inpainting（MIT）**。

**长期 · 底座自研与沉浸升级（壁垒）**

6. 以 **Canvas360 / DiT360（MIT）** 为生成底座，训练「手机局部图→完整球面」的 in-context 补全模型，形成自有能力；用 **LayerPano3D（Apache）/ PanSplat（MIT）** 走可漫游 3D 全景。

与《手机全景刚需调研》的呼应：近期第 1–3 步对应 N12 的「天顶/脚下补全」Quick Win；中期第 4–5 步对应 N12 的「扩散外扩」Big Bet。

## 八、效果与工程性横评

| 维度 | 说明 |
|---|---|
| 纯补全效果（不看许可） | PanoDiffusion ≥ 可商用扩散(SDXL+LoRA) > Cylin-Painting > 确定性(LaMa/PanoTwist/Stitching) |
| 可商用里的补全效果 | **Cylin-Painting（外扩）** + **LaMa（补洞兜底）** + **3d-pano-inpainting（3D 一致）** 是目前许可干净的最优解；扩散外扩靠自研/SDXL 组合补齐 |
| 生成底座质量天花板 | DiT360（SOTA）/ Canvas360 最高，但需二次开发才用于补全 |
| 球面一致性（极区/接缝） | DiT360 三重约束最讲究；Cylin、PanoDiffusion 有 wrap 设计；LaMa/PanoTwist 需自己处理球面 wrap |
| 显存/部署 | 确定性路线(CPU)与 Cylin/LaMa 最省；PanoDiffusion/扩散外扩需较大 GPU；DiT360≈37GB（量化可降） |
| 接入难度 | LaMa/OpenCV/PanoTwist 最易集成；Cylin 中等；3d-pano-inpainting/扩散工作流/DiT360 改造偏重 |

「效果最好的几个开源可商用」的直接回答：**可商用的第一梯队是 Cylin-Painting（MIT，专职外扩）+ LaMa（Apache，补洞）+ 3d-pano-inpainting（MIT，3D 一致补全）；若允许二次开发，用 Canvas360 / DiT360（MIT）作生成底座可把质量天花板抬高。而 PanoDiffusion 与两个 ComfyUI VR 节点虽效果最好，却都禁止商用，只能当技术参照。**

---

## 九、风险与待验证

第一，**许可会变且分代码/权重两层**：GitHub 探测的 spdx 只覆盖仓库代码，预训练权重可能另有单独条款；商用前需分别核对「代码 LICENSE + 权重/模型卡许可 + 基座模型许可」三处，并留意版本更新。

第二，**权重是否真释放需确认**：Cylin-Painting、3d-pano-inpainting 代码齐，但可直接下载的预训练权重需进仓库/项目页核实；缺失则要先复现训练，成本另计。

第三，**球面几何与极区质量要实测**：论文/README 的效果图不等于自家手机素材上的表现，务必用真实残缺素材做 A/B（尤其 nadir、±180° 接缝、极地拉伸）。

第四，**训练数据版权**：扩散/生成底座的训练集含全景图库，商用对外交付时的版权敞口需评估；自训自有数据最稳，这也正好接《壁垒二期》的数据资产思路。

第五，**缺统一补全评测基准**：领域无公认的「补全质量」标准指标，建议自建评测集 + 主观打分 + 下游转化（如补全后作品发布率）三合一。

第六，**范围待你确认**：本报告按「**全景图片**补全（360 柱面 / 720 球面）」展开；若你实际关注**全景视频**补全、或想直接排一个 PoC 把近期组合（OpenCV+LaMa+Cylin）先跑通，告诉我，我可再出一版专题或做落地实施清单。

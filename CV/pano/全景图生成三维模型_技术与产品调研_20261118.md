## 0. 结论速览

1. **技术拐点已经出现。** 2026 年，全景输入的三维重建从"多视角摄影测量"转向"前馈大模型 + 生成式补全 + 3DGS"。标志是 PanoVGGT（CVPR 2026）、如视 Argus（ECCV 2026）、HY-World 2.0、PanoWorld（SIGGRAPH Asia 2026）、Marble 1.1 等一批工作同时落地。

2. **单张全景 → 3DGS 已可工程化。** 以 SPAG-4D 为代表的开源工具，用 DA360/DAP 估深度后做球面反投影，**2–3 秒**即可输出可浏览的 3DGS PLY；但单视点看不到的背后、遮挡区域是空洞，必须靠补全或接受"看得到的地方才真实"。

3. **多张稀疏全景 → 度量重建在 2026 年进入可用区间。** 如视 Argus 官方口径：5 m 内平均绝对误差 **3.71 mm**，全量居住场景约 **2.5 cm**，接近消费级 LiDAR 的 2 cm；PanoVGGT 以 MIT 许可证开放，Matterport3D 上 AUC@30 达 **0.902**、AbsRel **0.052**，可自部署。

4. **生成式世界模型解决"完整"，但不解决"准确"。** Marble 1.1 单次 1500 积分、3–5 分钟；HY-World 2.0 约 12 分钟/场景，输出 3DGS+Mesh；PanoWorld 可从户型+风格生成整屋全景并重建 3DGS。它们适合展示、原型、游戏/影视，不适合工程计量与文博档案。

5. **商用最现实的组合：**
   - **效果图/展厅漫游**：2.5D 深度分层兜底 + 单全景 3DGS 主路线 + 生成式补全增强；
   - **实景房产/博物馆**：多全景 Argus/PanoVGGT + 3DGS/Mesh + CAD/BIM；
   - **大场景园区**：分块重建 + 3DGS LOD 流式加载（如视、Matterport 路线）。

6. **最大的暗坑是 License，不是算法。** 原版 3DGS 光栅化（INRIA）为非商用；Apple SHARP、ETH PaGeR、Adobe OmniRoam 等权重也带非商用/研究限制。商用优先选择 **DA360/DAP（MIT）+ SPAG-4D 核心（MIT）+ gsplat（Apache-2.0）**，并对每个权重逐项核 LICENSE。

## 2. 概念边界：你说的"全景图生成三维模型"是哪一种

"全景图 → 3D"在行业里有四种完全不同的目标，选错路线会直接导致项目失败。

### 2.1 四种输入

1. **单张 ERP 全景**：最常见，也是"效果图全景"的形态。只有一个视点，背后与遮挡区域没有观测。
2. **多张稀疏 ERP**：房产、博物馆采集的典型形态，2–20 个点位，点位间可能只有门洞方向的窄重叠。
3. **全景视频**：连续帧，视差充分，适合 3DGS/NeRF；但数据量大、需要位姿。
4. **立方体贴图/双鱼眼**：相机原生格式，需先转 ERP 或直接在球面域处理。

### 2.2 四种"三维模型"

| 交付目标 | 典型表示 | 关键指标 | 适合路线 |
|---|---|---|---|
| **可漫游视觉** | 3DGS / NeRF / 分层 Mesh | PSNR/SSIM/LPIPS、漫游流畅度 | B/C/E |
| **可测量几何** | 点云 / Mesh / CAD | 绝对尺度、AbsRel、RMSE、mm 级误差 | D/F |
| **可编辑资产** | Mesh/GLB/FBX、语义分层 | 拓扑、UV、材质、部件关系 | C/F |
| **可仿真** | Mesh + 碰撞体 + 物理属性/URDF | 碰撞一致性、物理参数 | D/F（或 HY-World 类） |

### 2.3 三个硬约束

- **尺度**：单目/单全景天然尺度不确定。只有度量深度模型（DAP、Argus）或已知相机高度/标定物才能给出绝对尺度。
- **遮挡与空洞**：单视点全景的背后永远没有真实数据；3DGS 会在遮挡边缘出现"拉丝"、空洞、漂浮物。补全是"生成"，不是"恢复"。
- **一致性**：多全景之间的位姿误差会累积为墙体弯曲、重影、接缝；3DGS 对位姿误差非常敏感（如视 Argus 的核心卖点就是给 3DGS 提供 LiDAR 级位姿约束）。

## 3. 2026 年技术进展

### 3.1 全景深度与位姿：从"能估"到"可度量"

全景深度是整个链条的地基。2024–2026 的主线是：**把透视深度基础模型适配到球面域，并补上度量尺度**。

| 模型 | 发布 | 输入 | 输出 | 关键点 | License |
|---|---|---|---|---|---|
| **DA360** | Insta360，2025–2026 | 单张 ERP | 尺度不变/相对深度 | Depth Anything V2 + 循环填充 DPT 解码器，接缝/极点更稳 | MIT（部分资料记 Apache-2.0） |
| **DAP（Depth Any Panoramas）** | CVPR 2026，Insta360 | 单张 ERP | **度量**径向深度 | 球面几何 + 度量头；SPAG-4D 默认商用后端之一 | MIT/Apache-2.0（口径不一） |
| **PaGeR** | ETH Zürich，2026 | ERP/立方体 | 深度 + 天空 + 法线 | DA3 立方体多视几何，室外强 | CC BY-NC 4.0（非商用） |
| **SHARP** | Apple，CVPR 2025 | 单张透视 | 3DGS | 单图前馈、<1 秒、度量尺度 | Apple 模型许可（非商用） |
| **UniSHARP** | Insta360，2026 | 宽视场/鱼眼/全景 | 3DGS | 统一射线-距离空间，原生 ERP 支持 | 研究许可（需核） |
| **Argus** | 如视，ECCV 2026 | 单/多全景 + 针孔 | 位姿、深度、点图 | 前馈 Transformer，绝对尺度，毫秒级 | 商业闭源 |

**关键判断：**

- 如果只要"好看的可漫游"，DA360 足够；如果要"能量尺寸"，必须上 DAP/Argus 这类度量模型，或在场景中放标定物。
- 全景 ERP 的两个老问题——**左右接缝**和**极点拉伸**——2026 年已被循环填充、球面位置编码、立方体重投影等工程手段较好解决；但在玻璃、镜面、白墙、长走廊等场景，深度仍会显著退化。
- Argus 的路线值得注意：它不是"更好的深度模型"，而是**用大规模真实空间数据学习"位姿+深度+点图"的联合先验**，再把结果作为 3DGS 的几何约束。这解释了它为什么强调"让 3DGS 不再必须依赖 LiDAR"。

### 3.2 前馈重建：一次前向出位姿、深度、点云

**PanoVGGT（CVPR 2026，MIT）** 是这一方向的代表性开源工作：

- 输入 1–N 张**无序** ERP，单次前向联合预测相机位姿、深度、点云；
- 球面感知位置编码 + 全景三轴 SO(3) 旋转增强 + 随机锚定，解决全局坐标系歧义；
- 官方高分辨率 checkpoint（518×1036，3 帧）在 Matterport3D：AUC@30 **0.902**、AUC@15 0.854、AbsRel **0.052**、δ<1.25 **0.971**；Stanford2D3DS：AUC@30 **0.917**、AbsRel 0.046；AerialGo：0.998 / 0.026；
- 附带 PanoCity 户外全景数据集（密集深度 + 6-DoF 位姿）；
- **MIT 许可证**，代码、权重、Gradio demo 均已开放。

**Argus（ECCV 2026，如视）** 是闭源商业对照：

- 支持单张/多张全景、普通针孔、AI 图片；一次前馈输出**绝对尺度**的位姿、深度、点图；
- 官方口径：5 m 内平均绝对误差 **3.71 mm**；真实子集 ATE 从 MapAnything360 的 0.134 降至 **0.096**（约 -28%），合成子集从 0.087 降至 **0.027**（约 -69%）；全量居住场景约 **2.5 cm**；
- 推理毫秒级，强调玻璃、镜面、毛坯房、长走廊等难点场景的稳定性；
- Argus 2.0（2026 年初）扩展到 3DGS 与精细 Mesh；如视 2026-09 起把 3DGS 能力产品化，支持全景图、全景视频、单反照片、普通视频输入，并做分块、流式加载，文件体积降到原来的 1/4–1/5。

**WorldMirror 2.0（腾讯 HY-World 2.0 组件）**：

- 统一前馈模型，一次预测深度、表面法线、相机内外参、稠密点云、3DGS 属性；
- 支持 50K–500K 像素的灵活分辨率、可选相机/深度先验、多 GPU FSDP；
- 在 7-Scenes/NRGBD/DTU 上，带全部先验时 Accuracy 可到 0.012–0.019（7-Scenes/NRGBD），属于当前开源前列。

**这一层的意义**：过去"多全景重建"依赖 COLMAP/SfM，遇到弱纹理、重复纹理、窄门洞重叠、旋转主导运动就容易崩；2026 年的前馈模型把这些场景的失败率显著压低，并且把"位姿+深度+点云"变成一次推理，给下游 3DGS/Mesh 提供了更稳的初始化。

### 3.3 生成式补全：把没拍到的部分"编"出来

生成式路线解决的是"单视点/稀疏视角根本看不到"的问题。它的输出**视觉上完整**，但几何是模型先验，不是观测。

**（1）One2Scene（ICLR 2026）**

- 单张图 → 全景锚点 → 前馈 GS scaffold（多视图立体匹配）→ 扩散模型精修；
- 关键设计：不直接把全景当一张图重建，而是投影成多个稀疏锚点视图，把任务转成多视图立体匹配，从而利用大规模多视图先验；
- 适合评估"单图生成可探索 3D 场景"的上限；代码/权重已开，但 LICENSE 未统一声明。

**（2）Matrix-3D（Skywork，2025-08，MIT）**

- 流水线：文本/图片 → 全景图 → 全景漫游视频 → 3D；
- 两条重建出口：
  - **优化式 3DGS**：逐帧深度（MoGe）+ 超分 + 3000 步 3DGS 优化，约 **10 GB** 显存，画质优先；
  - **Pano-LRM 前馈**：Transformer 一次前向出 3DGS，约 **80 GB** 显存，速度优先，目前限 480p 输入；
- 是理解"质量 vs 速度"取舍的好基线。

**（3）HY-World 2.0（腾讯，2026-04）**

- 四阶段：HY-Pano 2.0（全景生成，80B）→ WorldNav（VLM+NavMesh 轨迹规划）→ WorldStereo 2.0（17B，关键帧扩展+记忆）→ WorldMirror 2.0（1.2B，重建）+ 3DGS 学习；
- 输出 3DGS / Mesh / 点云，可直接进 Unity/UE/Blender/Isaac Sim；
- 官方口径：约 **12 分钟/场景**；Tanks-and-Temples 点云 F1 **43.16**；高分辨率相机位姿 AUC@30 **86.89**；深度 AbsRel **0.162**；与输入内容一致性 **94%**；
- 支持文本、单图、多图、视频；World Reconstruction 路径可直接吃多视图/视频；
- **License 为 Tencent 社区许可**，不是 Apache/MIT；第三方解读称有商用条件与地域限制，商用前必须读 LICENSE 原文。

**（4）PanoWorld（SIGGRAPH Asia 2026，Apache-2.0）**

- 面向"整屋"：户型引导的视点 + 风格参考 → 一致的全屋 360 全景；PanoWorld-LRM 把多视角全景重建为 3DGS；
- 官方推理数据：1024×512 单视 **6.1 GB / 0.17 s**，8 视 **27.5 GB / 1.45 s**；2048×1024 单视 **18.8 GB / 2.3 s**，8 视 **108 GB / 20.5 s**，12 视 OOM；
- 价值在于"整屋一致性"和"可导出 3DGS"，而不是单场景精度。

**（5）Marble 1.1 / Atlas（World Labs）**

- Marble 1.1：单图/多图（≤8）/视频/全景 → 可漫游 3D 世界；3–5 分钟；输出全景 JPG、碰撞 Mesh、SPZ（full/100k/500k）；
- 计费：**1500 积分/次**；1.1 Plus 1500–3000 积分；API 最低充值 $5≈6250 积分（折合约 **$1.2/次**，不含订阅）；
- Atlas（2026-09）为多模态世界模型，强调少量 2D 图像/视频帧的重建与仿真，是 Marble 的底层演进；
- 定位：**展示与原型**，不是测量工具；官方也承认复杂场景会有局部几何漂移。

**（6）Rein3D（2026）**

- "restore-and-refine"：从粗 3DGS 沿径向轨迹渲染全景视频 → 全景视频扩散修复 → 超分 → 作为伪真值更新全局 3DGS；
- 构建 PanoV2V-15K 数据集；适合离线高质量补全，计算重。

### 3.4 全景 3DGS：单张全景的工程化捷径

**SPAG-4D** 是 2026 年最值得关注的开源"单全景 → 3DGS"工程：

- 输入一张 ERP，输出可浏览的 3DGS PLY；每个像素沿球面射线反投影，颜色直接采样源像素；
- 四个生成后端：
  - **DA360**（默认）：约 2 s，2 GB 显存，接缝/极点稳，**商用 OK**；
  - **DAP**：约 3 s，3 GB，度量尺度，**商用 OK**；
  - **PaGeR**：约 15 s，12 GB，室外深度强，**非商用**；
  - **SHARP 360**：约 30 s，8 GB，逐面细节最高，**非商用**；
- 4096×2048、stride 1 约 560 万高斯、362 MB；stride 2 约 140 万、90 MB；stride 4 约 35 万、23 MB；
- 遮挡补全：OmniRoam v2 蒸馏（约 48 GB，WSL2）或几何补点；ArtiFixer3D 可做 14B 生成式重建（更重）；
- **核心 MIT**，DA360/DAP MIT，SHARP/PaGeR/OmniRoam 各自限制。

**PanSplat（CVPR 2025）** 走的是"两张广基线全景 → 球面 3D 高斯金字塔 → 4K 新视角"的路线，强调 4K 合成质量与跨数据集泛化；更偏"新视角合成"，不是"完整场景重建"，且依赖 INRIA 3DGS 光栅化，商用需谨慎。

**PanoImager（IROS 2026）** 针对一个非常现实的痛点：手持全景相机原地转、无人机悬停旋转、机器人定点环视时，**基线极短、SfM 容易退化**。它干脆去掉 SfM：前馈位姿/深度 → 几何条件扩散补全 → 深度引导 3DGS。适合作为"COLMAP 失败时的后备精化"。

### 3.5 2.5D 与结构化路线：低成本、可交付的另一极

不是所有"全景 → 3D"都需要真 3DGS。

- **Everpano + Krpano Depthmap**：在全景图上手工勾地面/墙面/天花板，反算几何并加厚度，导出 Krpano 场景。优点是**可控、轻量、移动端友好**；缺点是人工成本高、只能做有限视差，本质是"2.5D 立体全景"。
- **123看房（亦我）**：2D 全景 → 3D 模型 + 在线量房，官方口径深度误差 1.35%、100 ㎡ 约 10 分钟，适合房产/展馆的规模化生产。
- **如视/Matterport 的结构化产物**：点云 → 户型图/CAD/BIM，几何规则化、可测量，是工程与文博档案的真正交付物。
- **GISBox / 摄影测量**：多照片 → OBJ，适合物体/建筑，不是单全景路线；可作为"多视角补拍"的补充。

**结论**：如果目标是"效果图全景在 H5 里能走两步、有纵深感"，2.5D 的性价比远高于 3DGS；如果目标是"用户能自由转头、走近、看背面"，必须上 3DGS/生成式。

## 4. 产品盘点

### 4.1 国内产品

**（1）如视 Realsee：全链路最强，闭源**

- 采集硬件：G2（1299 元，16K/1.34 亿像素，10 m 深度）、伽罗华 P4（24K/3 亿像素，±10 mm，100 m）、庞加莱 R1（手持 128 线 LiDAR，≤3 mm，NIM 认证）；
- 算法：Argus 空间大模型（全景/多图 → 位姿、深度、点图；5 m 内 3.71 mm；全量 2.5 cm）；
- 产品：3DGS（2026-09 内测/上线）、Mesh、点云、户型、CAD、VR 漫游、AI 讲房、开放平台（2026-10-19）；
- 规模：官方口径 5300 万–5800 万套空间数据；服务贝壳、自如、雀巢、国网、清华校史馆等；
- 适合：房产、文博、园区、工程、需要"采集—重建—应用"闭环的 B 端项目；
- 限制：闭源、按项目/订阅计费、数据在厂商云；精确价格需商务。

**（2）众趣科技：VR 采集 + 3D 展示**

- SPACCOM Q5+ 等 3D 相机，结构光 + 视觉 SLAM，厘米级；VR-Lite 主打单人 10 分钟/100 ㎡；
- 优势：上手快、展示链路完整；劣势：精度与超大场景能力弱于如视（竞品口径）；
- 适合：房产经纪、展厅、中小商业空间。

**（3）123看房（亦我）：2D 全景 → 3D 的规模化玩家**

- 核心就是把 2D 全景图转成 3D 房源模型，提供 VR 看房、VR 带看、在线量房；
- 官方口径：深度误差 1.35%，100 ㎡ 约 10 分钟，测量误差 <1%；
- 适合：房产、展馆、文旅、教育等"快速铺量"场景；
- 限制：精度不足以做工程计量；更多是展示级 3D。

**（4）720云 / 酷雷曼：全景展示型**

- 720云：全景照片聚合 + 基础 3D 漫游，核心仍是点位跳转，适合文旅展示；
- 酷雷曼：VR 全景服务商，步进式漫游、热点，但缺在线测量/VR 带看；
- 适合：营销展示、预算有限、不需要空间计算的项目。

**（5）立方视界 / GISBox 等工具型**

- 立方视界：全景 + 3D 模型展示 H5 创作平台（上传 ERP/GLB，编辑器排场景、热点、发布）；
- GISBox：免费摄影测量（多照片 → OBJ），适合物体/建筑，不是单全景；
- 适合：作为展示层/补拍工具，不解决核心重建。

### 4.2 国外产品

**（1）Matterport：数字孪生的标杆**

- Pro3：LiDAR + 134.2 MP 全景，±20 mm @10 m，<20 s/站，E57 最远 100 m；
- 输出：3D 漫游、E57、MatterPak、BIM、户型图；
- 价格：Pro3 $3,995；Pro3 Plus $245/月起（含 50 空间）；订阅 Professional/Enterprise；
- 优势：生态成熟、精度可验证、海外房产/AEC 标准；劣势：硬件+订阅成本高、国内本地化弱、平台锁定。

**（2）World Labs Marble 1.1：生成式世界模型的"可交付"代表**

- 输入单图/多图/视频/全景，输出可漫游 3D 世界 + 全景 JPG + 碰撞 Mesh + SPZ；
- 3–5 分钟、1500 积分/次；API 可用；
- 优势：生成完整、视觉质量高、导出格式对 Web/引擎友好；劣势：非度量、复杂场景几何漂移、闭源云服务。

**（3）SpAItial Echo：空间智能新玩家**

- 官方定位：文本/图像/360 全景 → 持久化、可探索 3DGS 世界（SPZ/SOG + Mesh）；
- 2026 年热度高，但公开基准与独立复现少；适合跟踪，不建议作为唯一生产依赖。

**（4）Insta360：采集入口 + 研究外溢**

- X5（约 $549）/X3（约 $299）是消费级全景采集的主力；
- 研究侧 DA360、UniSHARP 开源，直接降低了"全景 → 深度/3DGS"的门槛；
- 注意：Insta360 相机本身不提供"一键全景 → 3D 模型"的完整 SaaS，需要搭配 SPAG-4D/自研管线。

**（5）Luma / Polycam / KIRI / Scaniverse：相邻路线**

- 以多照片/视频的摄影测量或 3DGS 为主，不是"单张全景"路线；
- 可作为"多视角补拍"工具，或作为消费级 3D 采集的对照。

## 5. 选型建议

### 5.1 按目标选路线

```
目标：能看、能走、能转头
├─ 只要小范围视差、移动端优先 → 2.5D 分层（Everpano/Krpano/自研 shader）
├─ 要自由漫游、能接受遮挡空洞 → 单全景 3DGS（SPAG-4D + DA360/DAP）
├─ 要"完整无空洞"、可接受生成 → 生成式世界模型（Marble/HY-World/Matrix-3D）
└─ 要多房间连续、大场景 → 全景视频 3DGS / 分块 3DGS（如视、PanSplat、Rein3D）

目标：能量、能出图、能对接 BIM
├─ 室内房产/文博 → 多全景度量重建（Argus/PanoVGGT）+ Mesh/CAD
├─ 工程/工业 → LiDAR/摄影测量（Matterport、如视 P4/R1、Faro/Leica）
└─ 仅做展示级量房 → 123看房/众趣

目标：生成概念场景/游戏原型
└─ Marble 1.1 / HY-World 2.0 / Matrix-3D / One2Scene
```

### 5.2 按场景选产品

| 场景 | 首选 | 备选 | 关键理由 |
|---|---|---|---|
| **效果图/展厅漫游（H5/小程序）** | 单全景 3DGS（SPAG-4D + DA360） | 2.5D 分层、Marble | 成本低、上线快；3DGS 视觉最好，2.5D 最稳 |
| **房产 VR 看房（真实房源）** | 如视 / Matterport | 众趣、123看房 | 需要度量、户型、带看、规模化采集 |

## 6. 效果图全景 → 可漫游 3D 的落地方案

> 这一节针对"只有一张效果图全景（或设计软件导出的 ERP），没有真实深度/多视角"的场景。它与实景采集的差别是：**没有任何真实几何先验，所有深度都是估的，所有背后都是生成的。**

### 6.1 先判断输入等级

| 等级 | 输入 | 可用信息 | 推荐路线 | 预期效果 |
|---|---|---|---|---|
| **A** | 设计源文件/引擎（UE、酷家乐、3ds Max 等） | 可导出深度图、相机参数、甚至 GLB | **直接导出 GLB/深度**，跳过单目深度 | 几何最准、成本最低 |
| **B** | 单张 8K ERP 效果图 | 只有 RGB | DA360/DAP 深度 → 3DGS；2.5D 兜底 | 视觉好，遮挡区需补全 |
| **C** | 多张同场景 ERP（不同机位） | 有视差 | PanoVGGT/Argus 位姿+深度 → 3DGS/Mesh | 几何更稳，可多房间 |
| **D** | 全景视频 | 连续视差 | PanSplat/Matrix-3D/Rein3D | 大场景最佳，但采集/算力高 |

**最重要的一条：如果效果图是从 3D 软件渲染出来的，优先走 A。** 让渲染端直接输出深度 pass、相机内外参、甚至 GLB，比任何单目深度模型都准，而且省掉补全。很多团队绕了一大圈做"全景 → 3D"，其实源头就有 3D。

### 6.2 推荐管线（P0/P1/P2）

**P0：可用的最小闭环（1–2 周）**

```
ERP 全景（4096×2048 或 8192×4096）
  → 预处理：去畸变/水平校正/接缝检查/天空分割
  → 深度：DA360（快、稳）或 DAP（要尺度）
  → 球面反投影：depth × ray_direction → 带色点云
  → 3DGS 初始化 + 短训练（或直接 SPAG-4D 输出）
  → 压缩：SPZ/SOG；导出 PLY/GLB
  → Web 查看器（SuperSplat/PlayCanvas/Three.js）
  → 兜底：2.5D 分层（Krpano/自研 shader）
```

- 目标：单场景 **< 1 分钟**出可浏览结果；移动端首屏 **< 3 秒**（压缩后 20–90 MB）。
- 适用：展厅、样板间、文旅、电商场景的"能走两步"。

**P1：质量增强（1–2 个月）**

- 遮挡补全：Rein3D / OmniRoam / 几何补点；对前景边缘、家具背后做定向补全；
- Mesh 导出：TSDF/Poisson → 减面 → UV/烘焙 → GLB，供不支持 3DGS 的引擎；
- LOD/流式：分块 3DGS + 距离 LOD，支持大场景；
- 语义分层：天空/墙面/地面/家具，支持换材质、换展品、碰撞；
- QA 自动化：极点/接缝/尺度/漂浮物/透明面检测。

**P2：多全景与结构化（3–6 个月）**

- 多全景：PanoVGGT（MIT）或 Argus API → 位姿/深度/点云 → 全局 3DGS；
- 结构化：墙面/地面/门窗检测 → 户型/CAD；对接 BIM/展陈系统；
- 生成式扩展：HY-World 2.0 / PanoWorld 做"未拍摄区域"的整屋生成；
- 数据飞轮：把每次重建的深度/位姿/人工修正回流，微调自己的深度/补全模型。

### 6.3 关键参数与质量目标

| 环节 | 建议参数 | 质量目标 |
|---|---|---|
| 输入分辨率 | ERP 4096×2048 起；细节场景 8192×4096 | 文字/展签可辨；极点无明显拉伸 |
| 深度模型 | DA360（默认）/ DAP（度量）/ PaGeR（室外，非商用） | AbsRel < 0.1（室内）；边缘无大面积拉丝 |
| 反投影 | 球面射线；按深度分位裁天空/远景 | 点云无大规模飞点；地面平整 |
| 3DGS | stride 1–2；SH 0–2；训练 3k–30k 步 | 新视角 PSNR > 25 dB（参考）；无严重漂浮 |
| 压缩 | SPZ/SOG；100k–500k splats 用于移动端 | 首屏 < 3 s；漫游 > 30 FPS（中端机） |
| Mesh | 面数 10 万–100 万；4K–8K 烘焙 | 展陈级视觉；碰撞体简化 |
| 补全 | 只补遮挡/边缘，不重绘主体 | 补全区与观测区过渡自然；不改变展品/文字 |

### 6.4 QA 清单

- **极点**：天顶/地面是否有拉伸、破洞、伪影；
- **接缝**：左右边界是否连续；深度图接缝是否跳变；
- **尺度**：门高/展台高/家具尺寸是否合理；有标定物时误差多少；
- **遮挡**：前景边缘是否"拉丝"；背后补全是否出现重复结构/文字错误；
- **透明/镜面**：玻璃、镜面、水面是否出现假深度/漂浮层；
- **一致性**：多房间墙体是否直；地面是否同一平面；重复纹理是否错位；
- **性能**：移动端首屏、内存、发热、帧率；
- **合规**：模型/权重 License、素材版权、人脸/车牌/隐私、AI 生成标识。

## 7. 工程、成本与合规

### 7.1 算力、时间与存储

| 任务 | 显存 | 时间 | 存储 |
|---|---|---|---|
| DA360/DAP 单张深度 | 2–3 GB | 1–3 s | 几 MB |
| SPAG-4D 单全景 3DGS | 2–8 GB | 2–30 s | 23–362 MB（随 stride） |
| 补全（OmniRoam/Rein3D） | 24–48 GB | 分钟–十分钟 | 中间视频/帧，数 GB |
| PanoVGGT 多全景 | 24 GB 级 | 秒级 | 点云/深度，数百 MB |
| HY-World 2.0 生成 | 16–80 GB | 约 12 min/场景 | 3DGS/Mesh，数百 MB–GB |
| PanoWorld LRM 8 视 2K | 108 GB | 20.5 s | 3DGS PLY |
| 大场景分块 3DGS | 24 GB+ | 小时级 | 数 GB–数十 GB |

**成本控制建议：**

- 单全景先用 stride 2/4 出预览，确认构图后再 stride 1 出正式版；
- 补全只在"用户会走到/看到"的区域做，不要全场景补；
- 3DGS 压缩优先于减面：SPZ/SOG 对视觉损失小、体积收益大；
- 大场景分块训练 + LOD 流式，避免一次性加载。

### 7.2 Web 分发与渲染

- **3DGS 查看器**：SuperSplat、PlayCanvas、Three.js + GaussianSplats3D；移动端优先 SPZ/SOG 压缩 + 低 splat 数。
- **Mesh 查看器**：GLB + Three.js/Babylon.js；兼容性最好，适合微信/小程序/低端机。
- **混合方案**：全景球（背景）+ 局部 Mesh/3DGS（前景）+ 深度视差，兼顾性能与真实感。
- **降级策略**：3DGS → 2.5D 分层 → 全景视频 → 静态全景；按设备能力自动切换。
- **SEO/分享**：全景/3D 页面需要 SSR 元信息、首屏封面、分享卡片；纯 WebGL 页面不利于收录。

2. **跨项目指标不可直接横比。** PanoVGGT 的 AbsRel、Argus 的 ATE、SPAG-4D 的 PSNR 来自不同数据集、分辨率、掩码与尺度对齐方式；表内并列仅用于量级参考。
3. **2026 年新工作多数缺少独立复现。** PanoWorld、PanoImager、Rein3D、One2Scene 等以论文/仓库为主，工程稳定性、长场景一致性、失败模式仍需自测。
4. **生成式模型的"完整"不等于"正确"。** Marble/HY-World/Matrix-3D 能补出背后，但补的是先验，不是观测；不能用于测量、验收、文物档案。

6. **价格波动。** Marble 积分、Matterport 订阅、如视项目价均可能调整；表中价格为 2026-11 公开口径。
7. **"全景图"定义不统一。** 本文默认 ERP 2:1；立方体贴图、双鱼眼、环物转台不在同一讨论范围，需单独处理。

## 8. 结论与行动建议

### 8.1 技术结论

- **单全景 3DGS 已经"够用"**：2–3 秒出结果，视觉远超 2.5D；但它是"看得到的地方真实，看不到的地方空洞"。
- **多全景度量重建已经"可用"**：Argus/PanoVGGT 把稀疏全景的位姿/深度做到 cm 级，给 3DGS/Mesh 提供了稳定初始化。
- **生成式世界模型已经"好看"**：Marble/HY-World/PanoWorld 能出完整可漫游场景，但几何不可测量，适合展示/原型。
- **2.5D 不会消失**：在移动端、低端机、效果图轻漫游场景，2.5D 的性价比仍然最高。

### 8.2 行动建议

| 优先级 | 动作 | 产出 | 周期 |
|---|---|---|---|
| **P0** | 搭建"单全景 → 3DGS"最小管线（DA360/DAP + SPAG-4D + SPZ + Web 查看器） | 10 个场景的对比样片、耗时/体积/帧率基线 | 1–2 周 |
| **P0** | 建立 2.5D 兜底模板（Krpano/Everpano 或自研 shader） | 低端机/弱网可用版本 | 1 周 |
| **P1** | 接入遮挡补全（Rein3D/OmniRoam）与 Mesh 导出 | "无空洞"版本、GLB 交付 | 1–2 月 |
| **P1** | 用 PanoVGGT 做多全景度量重建 PoC | 2–5 房间的位姿/点云/3DGS | 1 月 |
| **P2** | 评估 Argus API / 如视开放平台 / Marble API | 自研 vs 采购的 TCO 对比 | 2–4 周 |
| **P2** | 建立 License/合规清单与 QA 自动化 | 可上线的商用管线 | 持续 |

### 8.3 一句话选型

- **要快、要便宜、要能走**：SPAG-4D + DA360 + 3DGS。
- **要完整、要好看、可接受生成**：Marble 1.1 或 HY-World 2.0。
- **要量尺寸、出 CAD、做档案**：如视 Argus/P4/R1 或 Matterport Pro3。
- **要多房间、大场景、可流式**：如视 3DGS / PanSplat / Rein3D + 分块 LOD。
- **要今天上线、最低风险**：2.5D 分层 + 全景热点。

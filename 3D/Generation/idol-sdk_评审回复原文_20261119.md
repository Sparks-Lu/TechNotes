## What it is

`idol-sdk` is the inference SDK for **Idol**, a single-image → 3D Gaussian splat object model from Sperid Labs (released 2026-10-28, project page + HF weights + Gradio Space + a fal-hosted commercial endpoint). One object photo/render in → BiRefNet matting → crop → DINOv3 + FLUX.2 VAE conditioning → 0.66B rectified-flow DiT → octree + Gaussian decoders → a standard 3DGS `.ply` with 32,768–1,048,576 Gaussians, including invented sides.

## Verdict

Well-engineered, unusually clean for a three-week-old repo, and genuinely useful as an object-level image-to-3D primitive. But **"Apache-2.0, commercial-safe" is only half true**, the quality evidence is entirely self-reported, and there is no test/CI/eval infrastructure. Good for prototyping and internal tooling; not yet a drop-in production dependency without the fixes below.

## The license chain is the main problem

`config.json` in the weights repo points at two **gated third-party** encoders: `facebook/dinov3-vith16plus-pretrain-lvd1689m` (Meta "DINOv3 License", `license: other`, manual gating — commercial allowed but with export-control, attribution and must-ship-the-license-on-redistribution conditions) and `black-forest-labs/FLUX.2-dev` (FLUX.2-dev **Non-Commercial** license). So the default install path is not commercially usable, despite the repo being Apache-2.0.

The mitigation is already in the code and is a nice touch: `image_encoders={"flux2_vae": "/models/FLUX.2-klein-4B", ...}` swaps in `FLUX.2-klein-4B`, which I confirmed is `license: apache-2.0` and ships the same autoencoder under `vae/`. That closes the FLUX gap. **DINOv3 cannot be swapped for anything equivalent** — you must accept Meta's terms, and any product that redistributes the model/derivatives inherits those terms. Also flagged: `idol/models/birefnet.py` is a 491-line vendored copy of MIT-licensed BiRefNet with **no license/copyright notice** (TripoSplat is credited in the README but likewise has no `NOTICE`/third-party file; `dit.py` correctly keeps its Apache header). Add a `THIRD_PARTY_NOTICES` file before shipping.

## Code review: strengths

- Correctness care in the boring places: `save_ply` clamps opacity/scale before inverse-sigmoid/softplus so saturated values don't write ±inf, and applies a proper z-up→y-up rotation to positions **and** quaternions — most research repos get this wrong.
- Gated-access check runs *before* the ~3 GB download, with distinct messages for "not logged in" vs "not approved", plus `HF_HUB_OFFLINE` respected and caching in `_ACCESSIBLE_REPOS`.
- Device/backend handling is deliberate: cuDNN SDPA gated on sm80+, TF32 and attention backends restored via a context manager (no global leakage), `torch.compile` bound per-instance rather than globally.
- Only `safetensors` with `strict=True`, no pickle/`torch.load`/`eval`/subprocess anywhere; deterministic by seed; clean CLI + Python API with sensible flag surface.

## Code review: issues

**P1 — unverifiable quality claims.** No eval script, no test set named, no dataset size, no failure-case gallery, and the benchmark compares against TripoSplat/TRELLIS/LGM in the authors' own harness. LGM's higher PSNR is handily dismissed. Treat "best in 6 of 8 columns" as a vendor number until you rerun it.

**P2 — documentation contradicts its own data.** The README says "can run in under 2 seconds", but its GPU table's fastest row is 3.4 s (B300) and 19.1 s on a 4090. The gallery sizes (0.4 / 3.2 / 12.2 MB) also don't match what `save_ply` writes: 17 float32 properties ≈ 68 B/vertex → roughly 2.2 / 17.8 / 71.3 MB. The published figures only fit a compressed/quantized asset, so size your storage and CDN from the code, not the docs.

**P2 — AMD/ROCm is effectively unsupported.** The sm80+ guard uses `torch.cuda.get_device_capability`, which on ROCm reports HIP-derived numbers and passes, then `SDPBackend.CUDNN_ATTENTION` fails. Issue #12 and the timing report in #6 are open with no maintainer reply; PR #10 ("AMD Support") was closed unmerged. Same for three open issues overall — responsiveness is currently zero, and the contributor base is 5 one-commit people plus the org, i.e. single-team bus factor.

**P3 — nits worth fixing.** `decode_camera` doesn't reject negative `inverse_distance` (yields a negative radius); `has_real_alpha` treats one transparent pixel as "has alpha" and silently skips matting; crop coordinates use `int()` truncation so near-edge objects shift slightly; only `torch.manual_seed` is set; dependency floors without ceilings while relying on `dtype=` in transformers and `AutoencoderKLFlux2` in diffusers — version drift will bite; the `cpu` device is selectable but decoders are cast to fp16, so expect slow or failing runs; the SDK has no safety checker (the fal endpoint does), so content filtering is your problem if productized; no `py.typed`, no CI, no lint config despite `.ruff_cache` in `.gitignore`.

## Fit for your work

Object-level only — it is not a panorama/room reconstructor, so it does not compete with the pano→3D route in the report I delivered yesterday; it complements it for **exhibits, products, 环物-style assets**. Two practical notes: on a T4 (sm75) you lose the cuDNN fast path, so budget closer to the RTX 3080 number (~45 s) than the marketing "under 2 s", though 7.2 GB peak fits comfortably; and outputs are degree-0 SH only, so no view-dependent specular — glossy, transparent and thin structures will read flat, and the unseen sides are hallucinated, which rules out any measurement or authenticity-sensitive use.

## Recommendation

Adopt for prototyping now, behind three gates before production: (1) rerun the benchmark on 30–50 of your own messy photos, including glass/metal/thin objects; (2) lock the license posture — klein VAE swap plus a written DINOv3 terms review, and a third-party notices file; (3) add CI + a smoke test (one image, fixed seed, PSNR/vertex-count assertions) so weight or dependency upgrades can't silently change geometry. If you'd rather not carry that, the fal-hosted Idol endpoint is the lower-risk path — but note that a hosted commercial endpoint does not transfer any rights over the gated encoders' terms.

The repo is cloned at `idol_review/` in my working folder if you want me to run a specific check — e.g. compute exact PLY byte sizes per `--num_gaussians`, or draft the `THIRD_PARTY_NOTICES` and a CI smoke test.

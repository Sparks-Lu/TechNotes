## 1. 一句话与适用边界

**用二值掩码的形态学运算决定"哪里有墙、墙多厚"，用轮廓/中线的多边形简化决定"墙怎么走"，最后沿 Z 轴把二维多边形挤成体块，逐像素铺带顶点色的地板——得到可漫游、可测量、可再编辑的 3D 骨架。**

适用：真实尺度已锚定的户型/展馆平面（自有结构化数据，或识别管线输出的矢量多边形）。
不适用：曲面/异形墙占主导的建筑；需要施工图精度的构件（本方法产出的是**方案级体量**，不是 BIM 深化模型）；无任何尺度参照的营销渲染图。

## 2. Blueprint3D 的做法 vs 我们的改法

| 环节 | Blueprint3D（实测/读码所得） | 我们的改法 | 理由 |
|---|---|---|---|
| 构件识别 | `SplitFloor`：ResNet-50 + U-Net，四类 Background/Door/Wall/Window | **删掉**。直接用自有结构化平面（墙段+洞口+房间多边形），或复用《识别》备忘的 RoomFormer / Raster2Seq 输出 | 自有数据比像素分割更准且零训练成本；无权重、无数据集说明，重训代价高 |
| 房间识别 | `SemaFloor`：ResNet-50 + ASPP + U-Net，room/boundary 双头 | **删掉**，同上 | 同上 |
| 墙定位 | 对房间掩码 **erode**，用被腐蚀掉的带反推墙位 | 保留为**掩码输入模式**的备选；结构化输入模式下墙是已知线段 | erode 反推会吃掉共壁、产生双墙 |
| 掩码清理 | 方形结构元 closing/opening，阈值 `contour_squareness` | 保留，但把结构元做成**可选**（方形=正交假设，圆盘=弧形墙） | 方形结构元硬编码 Manhattan 假设，弧形墙会塌 |
| 墙厚 | 对墙掩码 **dilate**，参数 `wall_thickness` | 保留（像素域）；结构化域改为**中线 ± 半厚**偏置 | 偏置法能保留墙中线，供后续 DXF/IFC 用 |
| 洞口 | dilate 窗掩码得净空，另生成窗台(sill)/窗顶(header) | 保留三段式（下墙/洞口/上过梁），改为**由洞口参数直接生成**，不从掩码推 | 门洞、飘窗、高侧窗都能一致处理 |
| 成体 | 布尔阵列 → PyVista `ImageData` → 0.5 阈值等值面 → 沿 Z 挤出 | 保留"体素/等值面"作为掩码模式方案；**结构化模式用多边形挤出（更快、更干净、可导 IFC）** | 等值面产生大量无拓扑网格，不能进 BIM |
| 地板 | 逐像素 quad + 原图与分割图混合的顶点色 | 保留（展示性价比高），但补一条 UV 贴图轨道 | 顶点色文件体积大、不可换材质 |
| 输出 | `.obj` | `GLB`（展示）+ `SVG/DXF 分层`（专业）+ `IFC4`（BIM） | 见第 9 节 |
| 尺度 | 无 | **强制要求尺度锚点**（已知墙长或比例尺） | 《识别》第 4 节失败模式第 5 条 |

## 3. 输入约定与数据结构

两种模式，共用同一套挤出后端：

```jsonc
// 模式 A（首选）：结构化平面骨架 —— 与现有 params/模板库同构
{
  "scale": {"anchor_mm": 3600, "anchor_px_or_units": 360.0, "source": "业主提供客厅开间"},
  "height": {"story_mm": 2800, "slab_mm": 120},
  "walls":   [{"id": "W1", "polyline": [[0,0],[3600,0]], "thickness_mm": 200, "bearing": true}],
  "rooms":   [{"id": "R1", "name": "客厅", "polygon": [[...]], "finish": "wood"}],
  "openings":[{"id": "D1", "host_wall": "W1", "t_along_mm": 1200, "width_mm": 900,
               "sill_mm": 0, "head_mm": 2100, "kind": "door"}]
}

// 模式 B（兜底）：掩码图 —— 来自识别管线或扫描图人工涂抹
// masks: {wall, door, window, room_<id>}, 每张与平面同尺寸的 uint8 PNG
```

字段约定要点：

- `polyline` 一律为**墙中线**（不是两侧边），这是 DXF/IFC 对齐的前提。
- `openings.host_wall + t_along_mm` 用"贴在哪个墙上、沿线方向距离多少"表达，避免洞口坐标与墙几何不一致。
- `bearing`（承重）与 `slab_mm`（板厚）从第一天就带，后面对接拆改分析、造价、碰撞都靠它们。

## 4. 参数表（唯一需要人定的东西）

| 参数 | 建议默认值 | 作用域 | 调错的后果 |
|---|---|---|---|
| `story_mm` | 2800（住宅）/ 3500–6000（展厅） | 挤出高度 | 挑空区/管综空间失真 |
| `slab_mm` | 100–150 | 楼板厚度 | 层间错位、剖切不好看 |
| `wall_thickness_mm` | 承重 240 / 隔墙 120 / 展墙 100–200 | 中线偏置量 | 洞口净宽连锁错 |
| `contour_squareness` | 3–7 px（像素域） | closing/opening 结构元尺寸 | 太小→锯齿；太大→吃掉家具级凹凸 |
| `opening_head_mm` | 门 2100 / 窗 1500–2100 | 洞口上沿 | 上过梁高度不真实 |
| `sill_mm` | 门 0 / 窗 900 | 窗台高 | 剖面与光照错 |
| `polyline_simplify_eps` | 50 mm | 轮廓简化 | 太松→墙歪；太紧→顶点爆炸 |
| `double_wall_merge_mm` | ≤ 墙厚 1.2 倍 | 共壁去重 | 重复墙、Z-fighting |
| `kernel` | `square`（正交建筑）/ `disk`（弧形） | 形态学结构元形状 | 弧形墙被拉成阶梯 |

## 5. 算法六步

1. **归一化**：统一到毫米坐标（模式 B 则按 `scale` 做 px→mm）；开口方向、原点居中。
2. **墙带构造**：模式 A 由中线 `offset ± thickness/2` 生成墙多边形；模式 B 用房间掩码 `erode` 反推墙带 + `dilate(wall)` 补厚。
3. **清理**：形态学 closing→opening（模式 B）、共壁合并、小于阈值的碎块丢弃、多边形 `approxPolyDP` 简化并**强制正交化**（把接近 0/90° 的角度吸到轴上，展墙可关闭）。
4. **洞口布尔**：沿墙生成洞口棱柱（`t_along ± width/2`，`sill..head`），从墙体减去；同侧自动生成窗台与上过梁体块（这就是 Blueprint3D 里 sill/header 的来源）。
5. **挤出**：墙多边形与楼板轮廓沿 Z 挤出（`story_mm`、`slab_mm`），房间地板逐像素 quad 或按多边形铺面，写顶点色或 UV。
6. **装配与导出**：按元素类型分组（wall / slab / opening / room / label），一次导出 GLB（展示）、SVG/DXF（专业）、IFC4（BIM）、JSON（回传给编辑器和校验器）。

## 6. 代码骨架（自研，不抄源码）

```python
# deps: numpy, shapely>=2.0, scikit-image, trimesh, ezdxf, (ifcopenshell)
import numpy as np
from shapely.geometry import LineString
from shapely.ops import unary_union, substring   # substring 自 shapely 2.0 起在 ops 下
from skimage.morphology import binary_closing, binary_opening, square, disk

def wall_polygon(w):
    """中线 → 带厚墙多边形（cap_style=2 = flat 端头，避免端点外凸）。"""
    return LineString(w["polyline"]).buffer(w["thickness_mm"] / 2.0, cap_style=2, join_style=2)

def clean_masks(masks, squareness=5, kernel="square"):
    """模式 B：对像素域掩码做形态学清理（对应 Blueprint3D 的 Shape.py / morpho.py 思路）。"""
    se = square(int(squareness)) if kernel == "square" else disk(int(squareness))
    return {k: binary_opening(binary_closing(m, se), se) for k, m in masks.items()}

def opening_prism(o, host):
    """在所属墙上开洞：沿线取一段，稍外扩保证布尔干净；返回 2D 洞口投影 + z 区间。"""
    line = LineString(host["polyline"])
    hw = o["width_mm"] / 2.0
    a = min(max(o["t_along_mm"] - hw, 0.0), line.length)
    b = min(max(o["t_along_mm"] + hw, 0.0), line.length)
    pad = host["thickness_mm"] / 2.0 + 1.0          # 外扩，防止共边布尔留下碎面
    prism = substring(line, a, b).buffer(pad, cap_style=2)
    return prism, (o["sill_mm"], o["head_mm"])

def build(plan):
    """返回 (墙总体, 开洞后的墙总体, 每个洞口的 (投影, z 区间))。"""
    by_id = {w["id"]: w for w in plan["walls"]}
    walls = unary_union([wall_polygon(w) for w in plan["walls"]])   # 共壁在此合并
    holes = {o["id"]: opening_prism(o, by_id[o["host_wall"]]) for o in plan["openings"]}
    body = walls.difference(unary_union([p for p, _ in holes.values()])) if holes else walls
    return walls, body, holes
```

挤出与装配（竖直方向在这里落地：墙挤到层高，洞口按 z 区间切成窗台 / 玻璃 / 上过梁三段）：

```python
import trimesh

def extrude(polys, z0, z1):
    return trimesh.creation.extrude_polygon(
        polys, height=z1 - z0,
        transform=trimesh.transformations.translation_matrix([0, 0, z0]))

def assemble(plan):
    _, body, holes = build(plan)
    story, slab = plan["height"]["story_mm"], plan["height"]["slab_mm"]
    parts = {"wall": extrude(body, 0, story),
             "slab": extrude(unary_union([r["polygon"] for r in plan["rooms"]]), -slab, 0)}
    for prism, (sill, head) in holes.values():          # 洞口补三段，避免留穿堂缝
        parts.setdefault("sill",   []).append(extrude(prism, -slab, sill))
        parts.setdefault("glass",  []).append(extrude(prism, sill, head))
        parts.setdefault("header", []).append(extrude(prism, head, story))
    return parts
```

导出（同一次构建，三份产物，避免二次几何漂移）：

```python
def export(scene, outdir):
    scene.glb.export(f"{outdir}/plan.glb")            # ① 展示：Web/浸展/小程序
    to_dxf(scene, f"{outdir}/plan.dxf")               # ② 专业：分层 WALL/DOOR/WINDOW/ROOM + 真尺度
    to_ifc4(scene, f"{outdir}/plan.ifc")              # ③ BIM：见 9.2 映射表
```

> 说明：以上骨架刻意留出模式 B 的形态学入口，但主用模式 A（结构化）。骨架里的差集/缓冲逻辑是标准 GIS/CG 做法，不含 `Blueprint3D` 代码。

## 7. 必须避开的五个坑

1. **共壁重复**：两侧房间各生成一块墙 → 厚度翻倍、Z-fighting。用 `unary_union` 合并并把房间边界视作共享边。
2. **erode 反推墙位**（掩码模式）：腐蚀会吃掉承重墙细节，且与检测到的 wall 掩码冲突。规则：**有 wall 掩码就只 dilate，不 erode**；erode 仅用于补漏。
3. **正交化过度**：吸附角度到 0/90° 时，展墙/艺术隔墙常被拉坏。给每个元素加 `orthogonal: true|false` 开关。
4. **洞口与墙不同步**：改了墙长忘了改洞口偏移，洞滑到墙外。把洞口写成 `host_wall + t_along` 并在重建时重算（本备忘第 3 节的约定就是为此）。
5. **无尺度锚点**：没有参照尺寸就不要写 `mm`，一律以 `unit` 输出并在 UI 上标注"相对尺寸"，避免被当成可测量结果（对应《识别》备忘的合规提醒）。

## 8. 验收指标

| 指标 | 目标 | 量法 |
|---|---|---|
| watertight（闭合性） | 墙/板实体 100% 闭合 | `trimesh.is_watertight` |
| 洞口有效性 | 100% 落在所属墙内，净宽误差 < 5 mm | 布尔交校验 |
| 重复墙 | 0 处 | 共壁 IoU 检查 |
| 面数/体积 | 单套住宅 ≤ 20 万三角面 / GLB ≤ 8 MB | 导出统计 |
| Web 首屏 | ≤ 3 s（GLB + Draco/meshopt） | Lighthouse + 真机 |
| **edit-cost（人工返工时数）** | 每套 ≤ 15 分钟 | 按《识别》备忘 3.3 的指标定义记录到工单 |

> edit-cost 是这里唯一真正对齐业务的指标：几何再"漂亮"，返工时间长就是不合格。

## 9. 与《户型图识别》第 7 节"到 CAD/BIM/IFC 路径"的衔接

《识别》第 7 节结论是："**AI/识别只负责出底图（带图层与真尺度的 DXF 或结构化 JSON），再由 CAD/Revit/ArchiCAD 二次建模；识别→IFC 一步到位的产品在 2026 年仍不存在。**"本备忘的定位就是**把"底图 → 3D 骨架"这一段自研吃掉，同时把"骨架 → BIM"这一段以标准格式交出去**，不宣称一步到位。

### 9.1 三条导出轨道

| 轨道 | 格式 | 消费者 | 本模块职责 | 交出去之后的事 |
|---|---|---|---|---|
| 展示 | `GLB`（Draco/meshopt）+ 可选 `SPZ` | 浸展/ExpoVR 网页、小程序 | 全部在本模块内完成 | 换展品、加热点、SEO 首屏 |
| 专业 | `DXF`（分层：WALL/DOOR/WINDOW/ROOM/DIM）+ `SVG` | 设计师、造价、拆改评估 | 输出**墙中线 + 真尺度 + 图层** | 深化、出施工图 |
| BIM | `IFC4`（或 Revit/Dynamo 可吃的 JSON） | 项目方、物业、数字孪生 | 输出**元素级实体与属性**（不做 MEP/材质深化） | 构件深化、工程量、运维 |

### 9.2 元素 → IFC 映射表

| 我们的元素 | IFC4 实体 | 必带属性 | 说明 |
|---|---|---|---|
| 墙（中线+厚+层高） | `IfcWall` / `IfcWallStandardCase` | `HasProfiles`（厚度）、材质层 `IfcMaterialLayerSetUsage`、`LoadBearing` | 必须从**中线+厚度**建模，不能用挤出壳，否则 Revit 里不可编辑 |
| 门 | `IfcDoor`（`Opening` 先挖洞） | `OverallHeight/Width`、`OperationType` | 洞口用 `IfcOpeningElement` |
| 窗 | `IfcWindow` + `IfcOpeningElement` | `OverallHeight/Width`、窗台高（`PredefinedType`） | 与展示轨道共用同一 `host_wall + t_along` 参数 |
| 楼板 | `IfcSlab`（`FLOOR`） | `Thickness` | 层间关系靠 `IfcBuildingStorey` |
| 房间 | `IfcSpace` | `LongName`（客厅/展厅）、面积 | 与我们的 params 房间语义一一对应 |
| 展墙/隔断 | `IfcWall` + 自定义 `Pset_ExhibitionWall` | 是否可拆、面层材质、挂件承重 | 这是展陈场景的差异化字段，别塞进标准属性 |

### 9.3 自动 / 人工分界

- **可以全自动**：墙中线、洞口、楼板、房间闭合、体量、GLB/SVG/DXF 分层、IFC 骨架实体。
- **必须人工或规则库**：材质与面层构造（IFC 材质层）、结构与消防属性（耐火等级、疏散宽度判定）、MEP、家具深化、异形/曲面墙。
- **禁止自动**：把"方案级体量"当作竣工尺寸对外承诺（展示级 ≠ 计量级，涉及测绘资质与精度认证）。

## 10. 落地计划

| 优先级 | 事项 | 产出 | 周期 |
|---|---|---|---|
| P0 | 模式 A（结构化平面 → GLB）打通，含共壁合并、洞口三段、watertight 校验 | 10 个真实展陈/住宅平面的体量 + 指标报告 | 1–2 周 |
| P0 | 参数表进配置（层高/墙厚/窗台…），按业态预设（住宅/展厅/门店） | 可被 LLM 填槽的 JSON Schema | 3 天 |
| P1 | 模式 B（掩码 → 形态学 → 挤出）作为兜底，接识别管线的矢量输出 | 掩码模式可用 + 与模式 A 一致性对照 | 2–3 周 |
| P1 | DXF 分层 + SVG 导出，真尺度与图层验收 | 设计师可直接打开的 DXF | 1 周 |
| P2 | IFC4 导出（墙中线+厚度模型），Revit/Dynamo 回读验证 | IFC 骨架通过第三方软件校验 | 3–4 周 |
| P2 | edit-cost 埋点：记录每套人工修正动作与耗时，反推该自动化哪一步 | 返工热力图 | 持续 |

> **提级触发条件**：若第 11 节的缺陷 2 / 3 / 4（无构件语义、洞口非构件、面积不可信）挡住商用交付，则把本表中"墙中线 + 构件语义"的改造从 P2 提为 P1，同时把掩码模式（现 P1）降级为**仅内部草模工具**，不再对客户暴露。

## 11. 方案固有缺陷与能力边界（复盘补充）

> 分工说明：**第 7 节是"实现层会踩的坑"**（共壁、erode、正交吸附、尺度锚点——都能靠工程手段解决）；**本节是"表示层固有的、改不掉的缺陷"**——由"像素掩码 + Z 轴挤出"这个选择本身决定，只能回避不能修复。
> 一句话结论：**缺陷不在实现细节，而在表示方式。这套方案天生只能产出"方案级死壳"，表达力、构件语义、面积规范性三处封顶。**

### 11.1 改不掉的结构性缺陷（★）

| # | 缺陷 | 具体表现 | 为什么改不掉 |
|---|---|---|---|
| **1 ★** | **只能表达"竖直墙 + 水平板"** | 层高恒定、墙必垂直、楼板必水平；坡屋顶、挑空、错层、变截面墙、悬挑、弧形墙、幕墙分格一律做不出 | 挤出方向固定在 Z 轴；方形结构元等于把 Manhattan 假设焊进算法，`kernel=disk` 只减少阶梯，不等于能画曲线 |
| **2 ★** | **没有构件语义，只有实体外壳** | 输出是"看着像墙的一团几何"：无墙-墙连接关系、无 T/L 角部密封、无构件分类；剖切露缝、碰撞体失真、进不了 Revit/ArchiCAD 参数体系 | 掩码域里没有"构件"这个对象，只有前景/背景像素。这正是本备忘把主用路径改成模式 A（墙中线 + 厚度）的唯一理由 |
| **3 ★** | **洞口是"挖掉的洞"，不是"装上的门窗"** | 只保证有洞，不产生门窗构件：无开启方向、门垛、窗框、过梁、幕墙分格；斜墙/厚墙上的洞口投影处理很脆 | dilate 掩码表达的是净空，不是族（family）与宿主（host）关系 |
| **4 ★** | **面积与工程量系统性不可信** | 面积 = 像素数 × px²_mm，边界半格误差随周长累积；规范算法走墙中线/内净尺寸。用来出套内面积或造价，**误差是固定方向的，不是噪声** | 像素域与计量域几何定义不同，永远差半个墙厚 |
| **5 ★** | **尺度不能自证** | `anchor_mm` 缺失或给错时，模型"看着完全合理"但所有尺寸成比例错，人眼看不出比例错 | **最危险的失效模式：它不报错，只是悄悄全错。** 唯一防线是强制锚点 + UI 上标注"相对尺寸" |

### 11.2 可以压小、但成本会转嫁的缺陷

| # | 缺陷 | 表现 | 缓解与代价 |
|---|---|---|---|
| 6 | **分辨率依赖** | 墙厚由 dilate 半径决定，与图纸 DPI/线宽耦合；同一参数在 300DPI 扫描与手机拍照上给出不同墙厚；斜墙必出阶梯 | 统一到毫米域；代价是重采样引入新误差 |
| 7 | **共壁与布尔退化** | 两侧房间各出一块墙 → 厚度翻倍 + Z-fighting；erode 反推吃掉承重墙细节并与 wall 掩码冲突；共边差集留碎面/退化多边形 | `unary_union` 只解决合并，不回答"这面墙属于谁" |
| 8 | **误差被非线性放大** | 分割 IoU 0.9 听着不错，挤出后 0.1 的边界偏差就变成"墙偏 10 cm / 门洞错位 / 房间不闭合"的**结构性**缺陷 | 所以验收只看 edit-cost（第 8 节），不看 F1 |
| 9 | **拓扑不保证 watertight** | 悬空墙、孤岛、孔洞、非流形边都要后置 repair + 校验 | "跑一遍 + 一轮清理"，不是"跑一遍就好" |
| 10 | **面数随像素线性增长** | 8K 平面图轻松出百万级三角形，Web 端不压缩上不了 | 减面 + Draco/meshopt，又回到细节丢失 |

### 11.3 业务后果：它到底能替代什么

直角硬边、无踢脚/收口/倒角、顶点色没有 UV 与材质、光照靠烘——**对外汇报或效果图级别的需求，一眼能看出"这是拉伸出来的"**。

> 它能替代的是 **草模（massing block）**，替代不了 **深化模型**。

### 11.4 对应的取舍

- 要**快、能漫游、能看展线/动线/碰撞** → 用掩码挤出，并接受它是草模。
- 要**进设计师工作流、出 DXF/IFC、接报价** → 必须走参数化表示（墙中线 + 厚度 + 洞口宿主关系 + 构件分类），掩码只作为"从图到中线"的一次性输入，**绝不作为最终数据结构**。
- **异形/曲面/坡顶是主场景** → 整条链路排除；改中线曲线 + 变截面扫掠（sweep/loft），或交人工建模。

## 12. 诚实边界

1. **未实机验证**：本备忘的所有数值建议（层高、结构元尺寸、面数/体积上限）来自通用工程惯例与读码推断，**未在本项目数据上跑过**；P0 的第一周就是去证伪它们。
2. **对 Blueprint3D 的理解有二手成分**：仓库结构、`license: null`、7 星、2026-01 停更、README 与代码不同步（无 CLI/GUI 入口）、无权重——均为我逐文件核到；但其论文出处/训练数据/精度无任何公开说明，**它的效果不可引用为技术成熟度证据**。
3. **本备忘不复制其代码**（无许可证），第 6 节代码为自研骨架，且尚未运行，接口名可能与最终实现不同。
4. **弧形/异形墙是已知短板**：属第 11.1 节缺陷 1 的具体表现；方形结构元与正交吸附都会破坏曲线，`kernel=disk` 只是缓解，真正的自由曲线墙需要另一条"中线 + 变截面扫掠"实现。
5. **"识别→IFC 一步到位"仍未成立**：本模块只承诺交出一份"可被 Revit/ArchiCAD 继续深化"的底图与 IFC 骨架，深化工作量仍需按第 9.3 节的分界评估。
6. **与《户型图生成》备忘的分工**：生成侧解决"平面骨架从哪来"（模板库/约束求解/标记语言），本备忘解决"有了骨架怎么立刻变成 3D"。两者接口就是这个 JSON Schema——把 `params` 槽位语法化后可直接被生成器填充，这也是 FMLM 那种"markup + 约束解码"思路可迁移到我们展馆骨架生成的具体落点。

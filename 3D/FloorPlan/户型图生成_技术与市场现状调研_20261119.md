> 调研时间：2026-11-19
> 范围：从"无中生有"到"可交付"的户型图/平面布局自动生成——含学术模型（矢量户型生成、文本/图条件生成、统一理解-生成-编辑）、生产端约束求解器、消费端家装全链路 Agent，以及支撑训练的数据集与市场格局。
> 方法：一手依据为 arXiv/会议论文与官方 GitHub/HF 卡片，厂商数据以官网、招股书、上市公司公告、监管与主流财经报道为准，第三方实测用于交叉验证。所有百分比与指标均标注口径（论文自述 / 厂商自报 / 第三方评测 / 未核实）。

## 0. 结论速览

1. **研究范式在 2026 年完成了一次清晰的转向**：从"用扩散模型画一张像户型的像素图"转向"**把户型当成结构化序列来生成**"。标志是 CVPR 2026 的两项工作——FMLM（标记语言 + 自回归 + 约束解码）与 HouseMind（VQ-VAE tokenization + 多模态 LLM）。二者共同点是**输出天然可解析、天然合法**，不再依赖"生成后再矢量化/修补"。

2. **指标跃迁幅度很大，但要正确解读**：FMLM 在图条件设定下 FID 3.41（HouseDiffusion 29.31、HouseGAN++ 48.44）、GED 1.21；HouseMind 生成 FID 1.91、理解任务房间匹配率 99.8%、编辑 Node F1 0.998。这些都是**论文自述、且主要在 RPLAN/Structured3D 一类规整数据集上**测得，与"能不能落地施工"之间仍有断层。

3. **专业交付端的主流并不是神经网络**：海外可核实的产品线（Finch3D、TestFit、Hypar、ARCHITEChTURES）几乎全部以**约束求解 + 参数化面积/邻接/结构网格**为核心，产出 DXF/IFC/RVT；生成模型负责的是"多样性与探索"，求解器负责"合规与可解释"。第三方实测给出的比例很直白：Maket 一次生成 32 个方案，**其中仅 6 个可建**。

4. **中国市场的竞争焦点已从"会不会生成"迁移到"能不能履约"**：飞流AI（金牌家居）2026-07 发布 3.1 版把自己定位成"空间理解智能体"，2026-10-29 与腾讯签战略合作，接入微信 AI 入口与云算力，披露累计访问约 60 万人次、月活约 4 万、意向转化率 10.81%、设计师双盲方案选择率 66%（均为公司披露口径）。酷家乐母公司群核科技已于 2026-04-17 港交所上市（00068.HK），2026H1 营收 4.05 亿元、AI 新应用收入 3,100 万元（+177%）。

5. **户型图本身正在变成"资产"**：群核的核心叙事是覆盖全国约 90% 户型的三维空间数据库 + 2,500 万注册用户 / 800 万设计师；大晓机器人 Kairos-HomeWorld 直接开源 **30 万套中国住宅平面图 + 5,000 个全屋仿真场景**用于具身智能训练。户型数据的角色从"营销图片"升级为"可批量发酵 3D 场景的工业原料"。

6. **开源侧的可商用性很弱**：主流生成模型的权重/代码许可证多数**未核实**，训练数据集（RPLAN、CubiCasa5K、FloorPlanCAD）普遍禁止商用；目前唯一明确可商用的矢量户型基准是 ResPlan / ResPlan-FP（CC BY 4.0，代码 MIT）。这意味着"自己训一个户型生成模型"在数据侧就要先过合规关。

7. **对我们的直接价值是"骨架生成器"**：户型/平面布局生成与既有的参数化模板库路线是同一问题的两种解法——**模板库=离散槽位 + 规则反算；FMLM 式 markup=语法化表示 + 约束解码**。后者提供了把 params 槽位正式语法化、并保证输出 100% 合法的工程范式，可直接迁移到展馆平面骨架生成。

8. **不建议现在就押"端到端生成方案"**：2026 年的现实分工是——用 LLM/多模态做**需求解析与约束生成**，用求解器/模板做**布局落地**，用生成模型做**候选多样化与视觉呈现**。三段式比端到端可控得多，也更符合交付验收。

### 1.1 四条技术路线总表

| 路线 | 输入 | 输出 | 代表方案 | 评价指标量纲 | 可否直接交付 | 生产可用性 | 来源 |
|---|---|---|---|---|---|---|---|
| **A 结构化矢量生成**（房间多边形+门+类型） | 邻接图 / 轮廓边界 / 无条件 | SVG/矢量、可解析几何 | FMLM、HouseDiffusion++、Graph2Plan、GSDiff | FID、IoU、GED | 几何可用，需人工深化 | 研究可用，产品少见 | S1 S2 S7 |

## 2. 概念边界：四种"户型图生成"不是一件事

| 说法 | 实际要的东西 | 该用哪条线 | 常见误配 |
|---|---|---|---|
| "给一块地，排出 50 套房 + 车位" | 可行性 + 合规 + 指标 | C（约束求解/强排） | 用扩散模型生成→几何合法但不可建 |
| "把 80㎡ 做成三种布局给我看" | 多样化候选 + 面积合理 | A + C | 用 LLM 直接吐坐标→拓扑不稳 |
| "我说'三室一厅主卧朝南'就出图" | 语言→结构 | B（token 化 / markup） | 用文生图模型→无结构、无尺寸 |
| "业主上传户型，出效果图+报价" | 方案 + 供应链 | D（消费级 Agent） | 只做效果图→无法落地（京东/阿里/贝壳的家装 AI 普遍被指卡在这一步） |

三条判定线：

- **尺度**：C/D 输出带真实毫米/米尺寸，A/B 多数在归一化网格（如 FMLM 的 256×256 量化）里工作，**没有真实尺度就进不了施工**。
- **合法性**：A/B 靠"约束解码"（FMLM 的语法 mask）或求解器（C）保证不重叠、不越界；纯扩散/GAN 是"先生成再修补"。
- **可交付物**：专业端要求 DXF/IFC/RVT；消费端要求 CAD+报价+VR。只出 PNG 的方案在 2026 年已基本不构成竞争力。

## 3. 技术进展：2021 → 2026 的范式迁移

时间轴：HouseGAN++（2021，图条件 GAN）→ Graph2Plan（2022，边界+图）→ HouseDiffusion（2023，属性化扩散）/ LayoutGPT（2023，LLM+求解）→ HouseDiffusion++、GSDiff、ChatHouseDiffusion（2024）→ **FMLM、HouseMind、SAGE、MANSION（CVPR 2026）**，同期 Kairos-HomeWorld（2026-06）把户型生成推成"数据工厂"。

### 3.1 从像素到 token：FMLM 的标记语言路线

FMLM 的贡献不是"更大的模型"，而是**表示法**：定义一套 Floorplan Markup Language，把房间/门编码成"标签 + 坐标 + 索引 + 类型"四类 token，坐标用一维化 $z=x+yW$（W=256）压成整数，序列文法固定为 `<condition> → <floorplan> → rooms → doors → front_door`。

工程意义有三点：

1. **一个模型统一四类任务**（无条件/边界条件/图条件/补全），不再"每任务一个架构"。
2. **约束解码在推理时把非法 token 概率置零**——门必须恰好两个端点、房间多边形不得与已落子区域重叠、门必须落在某房间边界上。于是"输出一定能解析"从概率事件变成确定性保证，代价几乎为零。
3. 两个反直觉但对落地极重要的消融：**房间按索引降序书写**把 FID 从 94.57 拉到 25.50（大房间先落子给小房间提供空间参照）；**排列增强**去掉后 FID 从 14.17 恶化到 24.36（+72%）。

局限（论文自述）：仅支持单层；8 房间以上因训练样本不足 FID 从 3.41 升到 4.64；256×256 坐标量化会丢精度。

### 3.2 统一理解-生成-编辑：HouseMind 的 tokenization 路线

HouseMind 用**层次化 VQ-VAE**把平面图拆成"轮廓 token + 每个房间的（语义标签 token，几何 token）对"，房间码本是**条件式**的（编码时把轮廓一起喂进去，因此房间带着"我在全屋哪个位置、和谁相邻"的上下文）。之后把空间 token 并入 Qwen3-0.6B 的词表，三阶段训练（嵌入初始化→多模态预训练→指令微调）。

值得记住的对比：**0.6B 参数模型在生成/编辑上超过 7–8B 的通用 VLM**——作者的解释是"正确的表征比模型规模更重要"。理解侧 AdjAcc 从此前最好的 0.597 提到 0.990、面积误差降到 0.549 m²，推理 2–3 秒，单张 3090 可跑，这是它相对扩散方法在部署端最大的优势。

局限（论文自述）：编辑只支持简单房间增删；**未建模门窗与家具**；仅在 RPLAN 上验证；未与人类设计偏好/美学约束对齐。也就是说，HouseMind 生成的是"结构正确的房间划分"，还不是可交付的施工图。

### 3.3 场景级与多楼层：SAGE、MANSION、MajutsuCity

这三项把"户型生成"往上抬了一层，直接产出可用的三维环境，其共同点是**引入显式的正确性把关**：

- **SAGE（NVIDIA）**：Agent 协调 Generator + **视觉 Critic + 物理 Critic** 的迭代自优化。碰撞率 2.3%（基线 29–31%）、物理稳定性 99.8%（基线 51–59%）。消融显示物理 Critic 才是决定碰撞率/稳定性的那一项——这与消费级"只优化美观"的路线正好相反。
- **MANSION（AgiBot）**：Chief Designer→Floor Designer（每层 Bubble Diagram）→**Geometric Solver**（种子放置 + 层级空间划分，把气泡图变成精确几何）→Scene Instantiator。100% 可达性、0 边界违规；发布 MansionWorld 后指出：**现有 SOTA 具身智能体在四层楼任务上得分归零**，即场景难度已经领先于智能体能力。
- **MajutsuCity（中山大学）**：城市尺度，布局由 Diffusion U-Net 生成，但资产用**显式 3D**而非隐式神经渲染，因此可直接进引擎，并由 MajutsuAgent 支持五种物体级编辑。布局 FID 22.7 vs CityDreamer 139.6。

一个共同信号：**2026 年的主流不是端到端，而是"LLM 负责意图与调度、专门模块负责几何与验证"的多阶段流水线**（MANSION 的 Geometric Solver 与海外 Finch3D 的约束引擎在架构思想上同构）。

### 3.4 户型图作为数据工厂：Kairos-HomeWorld

大晓机器人（联合港中文 MMLab、深圳河套学院，2026-06-05）的四阶段：① 建筑骨架生成（基于真实户型图 + K-D 树结构化表示）② 家具布局精细化（俯视全局布局 + 第一人称细节填充）③ **物理闭环校验与修正**（微调 VLM 做递归校验，自动修"沙发挡门""物体穿墙"）④ 交互属性注入（表面中心放置，赋予密度/铰链/流形等物理属性）。同时开源 **30 万套中国住宅平面图 + 5,000 个全屋仿真场景 + 8,700 个资产**，规模显著大于 RPLAN（8 万）与 ResPlan（1.7 万）。

其自述局限值得引用："对动态物体支持有限、对极端户型覆盖不足、光照与材质真实感与真实环境有差距、实时生成能力较慢、场景编辑的细粒度控制不足"。

市场含义：户型图从"给业主看的信息"变成"给机器人喂的训练原料"，供给侧出现了新的数据生意（群核对外称要向物理AI供数据、大晓直接开源 30 万套），也带来新的授权与隐私问题（真实住宅布局属于可识别空间的元数据）。

### 3.5 经典基线与其真实局限

| 方法 | 路线 | 现在看来的真实短板 |
|---|---|---|
| HouseGAN++ | 图条件 GAN | 模式崩溃、多样性受限（FMLM 明确列为动机） |
| Graph2Plan | 边界+图 GNN | 需专门 GNN 编码器；FMLM 对照下 FID 34.20 |
| HouseDiffusion / ++ | 属性化扩散 | 生成后需后处理矢量化/修正，**无法保证合法** |
| GSDiff | 图结构扩散 | 无条件设定下 FID 15.02（FMLM 7.22） |
| LayoutGPT / Holodeck | LLM 直接/带求解 | 坐标可控性弱；Holodeck 靠 MILP/DFS 才稳住 |
| Tell2Design / ChatHouseDiffusion | 文本→户型 | 泛化有限，被 HouseMind 列为对比基线 |

### 4.1 中国：从"AI 出图"到"流量—设计—供应链"闭环

中国这条线的特色不是模型更先进，而是**商业闭环更完整**：

- **群核科技（酷家乐）**：2026-04-17 港股上市成为"空间智能第一股"。首日开盘 20.70 港元（较 7.62 港元发行价 +170%+），收盘 18.60 港元（+144.09%），首日市值报 316–351 亿港元（不同媒体口径）；盘中峰值有 660 亿（凤凰财经）与 837 亿（自媒体）两种说法，**未核实**。2026-06 出现阶段性回撤近 70%；摩根大通"中性/目标价 19 港元"、国泰海通"增持/24.9 港元"——分歧点在于**数据资产能否兑现为收入**（2026H1 物理 AI 相关收入占比仍低，主力仍是设计软件服务）。

需求侧的基本盘：2025 年住宅装饰装修行业规模突破 5.7 万亿元、存量房装修套数占比首次过半（约 52.3%，机构口径 56–65%），老房翻新需求 2020→2025 从 582 万户增至 1,054 万户（CAGR ≈12.6%）；2025 年新开工改造城镇老旧小区 2.71 万个 / 499 万户 / 投资 1,332 亿元（住建部）。"量房→户型→方案→报价"因此是刚性链路，而不是炫技场景。

## 5. 选型建议

**按问题类型给答案（先判类型，再谈模型）：**

| 你的诉求 | 首选 | 次选 | 不建议 |
|---|---|---|---|
| 要"合规 + 可进 BIM"的真实项目布局 | 约束求解（自研 CP-SAT/规则引擎，或采购 Finch3D/TestFit/Hypar） | 模板库 + 槽位反算（我们的既有路线） | 端到端扩散/LLM 直出坐标 |

- 海外 SaaS：Finch3D €79–$150/月（三源冲突）、Maket $20–149/月、TestFit $195/月起与 $15,000/年、Hypar $100/席/月。
- 国内 SaaS：三维家 58–128 元/月、专业版 2,999 元/年（厂商公开定价）；酷家乐为订阅 + 核豆混合模式；飞流 AI 对 C 端免费获客、B 端九天平台设计师付费。

## 6. 与我们业务的接口

1. **把 params 槽位"语法化"是低成本高收益的一步。** 现有路线（检索模板库 + 反算坐标）与 FMLM 的差异只在于表示层：若把户型/展馆骨架定义为受限语法（标签 + 坐标 + 索引 + 类型 + 约束段），就能直接复用"约束解码 = 100% 合法输出"这一性质，把校验成本从 qa_report 后处理前移到解码阶段。
2. **降序书写 + 排列增强**这类"数据表示小技巧"值得在我们自己的生成/检索排序实验里单独验证——FMLM 报出的 FID 差异（94.57→25.50）说明表示顺序的影响可能大于换模型。
3. **理解-生成-编辑统一（HouseMind 范式）**对应到展馆场景就是：既能回答"这个厅现在的分区是什么"，又能按指令改一个区域而不破坏整体——这是编辑类功能的产品价值最高的形态，比"重新生成一版"更能留住用户。
4. **物理/合规 Critic 不可省。** SAGE 的结论（物理 Critic 才是把碰撞率从 30% 压到 2.3% 的关键）与我们的经验一致：可计算的东西（尺寸、碰撞、通行宽度）应该交给校验器，而不是让模型"感觉合理"。
5. **数据资产的战略含义**：群核靠"约 90% 全国户型覆盖 + 800 万设计师"讲成了空间智能故事；大晓直接开源 30 万套平面图。对我们的展馆/全景业务，**结构化平面骨架 + 场景标注**这类自有数据同样具备被外部（具身/仿真）购买的潜在价值，值得在数据采集端就按"可复用资产"的标准存档与授权。
6. **不建议**：现阶段自研一个端到端户型生成大模型——数据（RPLAN/CC5K 禁商用、自采需规模）与许可两侧都受限，而求解器 + markup 语法 + 模板库的组合已能覆盖交付需求。

1. **未做任何实机复现**：FMLM/HouseMind 的指标全部来自论文与论文解读笔记，未在自有数据上重跑；两篇论文的官方代码/权重是否已发布、许可证为何，均未核实。
2. **跨来源拼接**：技术路线表与选型建议中的"生产可用性/不建议"属于我的综合判断，不是任何单一来源的结论；海外三家评测（ArchPulse、AIToolGiant、Archgyan）之间对 Finch3D 定价（€79 / $85 / $100–150）明显冲突，本表如实并列而不取中值。
3. **厂商口径集中**：三维家"95%+ 准确率 / 30 秒出 3D / 覆盖 90%+ 小区"、飞流"66% 双盲选择率 / 转化率 10.81%"、群核"覆盖约 90% 户型 / 2,500 万注册"、如视"3 mm / 15 分钟出 CAD / 5,800 万空间"均为自报或企业关联媒体报道，无第三方基准；其中"识别准确率超 90%"类百分比普遍未交代任务、数据集与指标定义。
4. **市值口径冲突**：群核首日/峰值市值存在 316 亿 / 351 亿 / 660 亿 / 837 亿港元四种说法，本报告只把 2026-04-17 收盘 +144.09% 视为可靠事实，峰值一律标未核实。
5. **行业统计存疑**："AIA 调查显示 60%→78% 事务所使用 AI" 出自单一博客转述，未见原始报告。
6. **中文 SEO 内容风险**：本次检索命中的部分 CSDN/百家号文章（如 floorplan-3d 相关长文、Mundo 相关软文）明显带营销或 AI 生成倾向，仅用于提取事实性线索（如产品存在性、导出格式），未引用其任何性能数字。
7. **范围取舍**：本报告不含"户型图识别/图纸解析"，那部分单独成文（见同目录识别篇）；两者的技术栈与许可问题差异很大，不建议合并阅读。
